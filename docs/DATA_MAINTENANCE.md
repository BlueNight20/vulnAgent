# 数据保留与遗留孤立记录维护

设置页提供“数据保留与孤立记录维护”。这是每次由操作者发起的操作，不会安装定时任务或自动清理用户库。开发验证只使用临时数据。

## 使用步骤

1. 填写清理截止时间（UTC）及至少保留的最近 N 项终态任务，默认分别为当前时间约 30 天前和 10 项。时间输入按 UTC 解释，不是本地时区。需要处理历史父任务缺失记录时勾选对应选项。
2. 点击“预览清理范围”，核对本页任务、孤立 taskId、各表行数、阻塞原因和数据范围。任务候选及孤立组各自每页 100 项，页码共同推进；总数包含阻塞项，可翻页查看。
3. 仅当确实要删除本页可清理数据时，输入“清理这些数据”，点击“备份并清理本页”。任务的全部证据、附件、冻结报告及其副本会随任务删除；审计和最小防重建 ID 保留。阻塞项始终保留。
4. 成功后记录备份目录、SHA-256 和审计 ID。需要继续时重新预览第一页，避免删除造成分页偏移。条件变化、任何数据库写入或服务重启可能使凭据失效，失败后必须重新预览，不自动重试删除。

仅支持当前 API 数据源的已迁移 SQLite 文件库；内存库可预览但不能执行，PostgreSQL 尚未适配。使用一个 API 实例管理该 SQLite 文件，不同时启动另一个实例共库执行任务。当前进程的在途工具计数不能跨实例共享，这项限制不会被 SQLite 写锁替代。用户已明确本次为单人自用，账号与多用户隔离不作为本次交付要求。

## 保留策略和阻塞条件

只选择 stopped / completed / failed 任务。结束时间须能被 SQLite 解析且严格早于截止；结束时间缺失或无效的任务保留。最近 N 项按有效结束时间排序保护，含晚于截止的终态任务。N=0 表示不增加最近数量保护，不会放行其他阻塞条件。running / paused / pending 不参与保留清理。

清理共用任务删除检查：任务或执行引擎仍运行、当前进程有在途工作、模型请求仍 reserved、调用待审批或待人工核实、会话未结束、Worker 正在运行、事件待消费，均阻止删除。queued 工作本身不是在途操作，满足其余条件时会随已结束任务一起清理。跨任务的证据附件/报告附件关联也会阻止清理，避免父对象的 CASCADE 删除其他任务或全局附件；单项任务删除接口同样检查。

“孤立记录”特指 25 张任务所属表和审计表中，taskId 非空且 tasks 没有该 ID 的记录组，用于处理安装归属约束前留下的数据。孤立组没有任务结束时间，不应用截止与最近 N 项；只有显式勾选才纳入预览。它们也需通过在途工作、会话、审批、事件及跨任务附件检查。未知审批和未结束会话的遗留组保留，操作者需先核查其历史状态。此功能不自动修补其他父子引用、JSON 证据 ID 或语义关系，也不读取外部路径/URI。

## 预览和执行的一致性

预览在串行只读事务中生成，不更新业务数据、不创建备份。服务以实例内随机秘密生成 HMAC，绑定规范化策略、本页候选和行数、阻塞状态、总数、过期时间及 SQLite 的 total_changes / data_version / schema_version。有效期十分钟；不保存可长期重放的清理计划，也不向客户端暴露秘密。

同一连接发生写入（即使行数不变）、其他连接提交、结构变化、回滚导致计数改变或服务重启后，旧凭据都可能不再有效。该设计较保守：其他任务的正常写入也可能使预览过期，建议在写入较少时操作。修改界面条件会立刻丢弃旧预览及确认文字。HMAC 是预览一致性校验，不是用户鉴权。

执行首先取得 SQLite reserved 写锁，重新生成并验证预览。锁保持期间，独立只读连接通过 Online Backup API 捕获已提交完整数据库；本连接尚未修改业务行，其他写连接不能在备份到清理之间提交。备份包含 WAL、原始 Unicode、二进制及报告副本，不包含主密钥或 .env。备份完成后重新检查本进程活动，防止备份 I/O 期间新出现的在途工作。

所有本页可清理任务和孤立组使用同一事务，记录 maintenance.applied（策略、本页原行数、任务名、备份位置和哈希），每个正常任务另有 task.delete 审计。正常任务按数据库触发器删除全部所属表；孤立组写入 task_deletions 后清理所属数据、将旧审计 taskId 置空。原审计实体 ID 保留，taskId=null 全局业务数据保持。补充的防重建 ID 阻止旧回调重新创建已清理的父任务。

备份失败不执行清理；审计、子表删除或提交失败会回滚本次所有业务修改和防重建 ID，不推送成功。已经生成的安全备份不因后续失败被删除，目录写入后端日志。提交后才发送审计及任务删除通知；通知失败不会把成功提交改成失败。同一凭据并发执行只有一个提交，后续请求因状态变化拒绝。

## 备份路径和恢复

VA_MAINTENANCE_BACKUP_DIRECTORY 可在启动配置中指定备份根目录。留空使用当前数据库同目录的 maintenance-backups。接口不接受客户端任意源库或备份路径。备份清单、完整性检查和新路径恢复复用 BACKUP_RECOVERY.md 中的工具，原主密钥须独立保管。

需要撤销清理时，先停止 API、核实外部工具状态，将完整备份恢复到新路径，再按 BACKUP_RECOVERY.md 切换 DB_PATH 与原主密钥；保留原库用于回退。恢复是整库恢复，不提供单任务自动合并，不能在新任务已写入后直接覆盖当前库。SQLite 空闲页、旧备份和日志不保证安全擦除。备份保留/轮换仍由独立维护命令控制。

## 验证

`npm run test:data-maintenance` 使用真实迁移文件库、WAL、Nest HTTP、校验管道、维护/任务/审计服务及备份 API。先在归属迁移前植入历史孤立记录，再升级；验证候选、最近数量保护、缺失/无效日期、运行和阻塞保留、两类各自分页、确认/过期/HMAC/实例重启及同计数写入失效。实际备份期间用另一 SQLite 连接写入，确认被锁拒绝；注入新在途活动、备份/审计/子表故障，检查整批回滚与备份保留。

成功清理验证整项任务和孤立组、全局与兄弟任务保留、审计归档、防重建及同凭据并发 200/409；从安全备份读取原任务、原文、证据 BLOB 和报告副本精确字节。额外覆盖跨任务附件级联阻止及内存库执行拒绝。界面测试验证挂载不请求、预览、确认文字、策略变更丢弃凭据、失败不重试、备份结果、分页和不可执行状态。以上不涉及靶机、真实工具命令或用户原业务库。
