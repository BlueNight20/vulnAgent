# 引擎与任务控制

更新：2026-11-03。当前支持单 API 实例、SQLite；控制请求与实际远端执行分开确认。

## HTTP 行为

`POST /api/tasks/:id/engine/start` 仅接受 pending / idle 任务。它与任务状态、task.start_requested 事件及审计在同一事务提交，返回 201 和 TaskSummary，表示请求已接受。不是返回 EngineSnapshot，也不代表 Planner 或远端工具已经启动。消费器随后创建执行上下文；使用 `GET /api/tasks/:id/engine` 查看实际快照。

`POST /api/tasks/:id/engine/pause`、`resume`、`stop` 共用任务中心的 applyAction；返回 201 和 TaskSummary。与 `/api/tasks/:id/pause`、`resume`、`stop` 使用同一事务和未消费控制请求检查，不能通过切换接口绕过冲突。未收尾的控制请求、关闭事件、重复启动或非法状态返回 409；无任务返回 404。设置页开关依旧独立控制启动/恢复与实际派发，见 RUNTIME_CONTROL.md。

启动只用于待启动任务；暂停任务使用恢复。running / needs_input 或 stalled 也允许显式恢复。completed / stopped / failed 不可通过启动、恢复、暂停或停止接口改写，须先使用任务的重新运行操作准备新预算轮次。重新运行事件尚未处理时启动返回 409，稍后确认状态再操作。

## 执行与中断

同一编排实例按任务串行处理生命周期动作；数据库事务重新读取状态。内部启动、暂停、恢复和停止将任务、执行记录及审计一起提交，随后才更新内存上下文、通知和请求会话动作。审计、数据库提交失败时不提前操作会话。任务字段使用局部更新，不用旧对象覆盖最新 Token 或成本。

事件处理失败保留未消费记录，下一轮重试。若控制已执行但事件消费确认失败，启动/恢复/暂停的已达状态可再次确认，不重复启动新运行或继续同一会话；终态后的过期恢复/关闭事件只收尾，不重启任务。控制的实际远程效果仍依赖已有 SDK / MCP 取消行为；数据库事务无法撤回已发出的远端操作。

无内存上下文的人工恢复会创建恢复执行上下文，沿用预算 epoch、已用 Token 和原任务开始时间，不刷新时间预算。任务“重新运行”才准备新的预算轮次。快照以持久化的暂停/终态及错误为准，待启动任务不显示旧上下文错误。

## 自动决策与 Worker 收尾

任务创建将目标、可选自动启动事件、审计及响应详情放在同一事务，失败不留下可执行任务。自动完成、需要输入、停滞和失败也将任务、运行记录及审计一起提交，再改变内存状态；失败会在提交后请求终止关联会话，取消效果仍需核实。

每轮异步循环保留当时的上下文和控制版本。暂停、恢复、停止或自动收尾使旧版本失效；旧循环的完成、停滞、失败、阶段或运行快照不能覆盖新控制状态。Planner 等待、重试及派发检查当前版本和持久化状态。暂停后立即恢复时，旧循环先结束，再安排当前版本继续，避免恢复请求被 busy 标志永久丢弃。这些版本仅用于单进程，不构成跨实例分布式锁。

Worker 收尾匹配当前 Worker ID 和会话 ID，旧运行或错误会话的通知不会改变当前任务。阶段/进度只局部更新，保留实时账本；事实计数读取或写入失败不提前移除活跃记录。通知失败每秒重试本地收尾，最多额外 3 次；不重放模型或 MCP 工具。耗尽后尝试原子记录任务失败并收尾会话，持续数据库不可用时只能写后端日志，操作人员修复后需核实状态并恢复。重试及续调度定时器在模块关闭时清理。

## 验证证据

`npm run test:engine-controls` 使用真实迁移的临时数据库、Nest HTTP、TasksService / OrchestratorService / AuditService 和固定会话工厂。覆盖两组接口交叉控制、重复请求、输入状态与终态约束、事件/审计/提交故障、内部启动/暂停/恢复/停止回滚、消费失败重试、恢复成功后消费确认失败的幂等重试、断开的 WebSocket、持久化快照、无上下文人工恢复及需要输入/停滞状态恢复。没有模型调用、靶机连接或真实命令。

页面交互测试验证 paused / needs_input / stalled 使用恢复接口、失败提示、请求期间互斥及成功后刷新。完整生产入口固定协议验证仍覆盖 Planner、多 Worker、证据、报告和进程退出恢复；这些证据不替代用户的真实靶机实测。

engine-controls 已扩展：创建的审计/目标/事件/提交故障、自动四种收尾审计故障整体回滚、真实挂起旧循环后暂停/恢复/停止及迟到异常、旧运行和 Worker 身份、事实计数读取失败、通知写入失败后重试及重试耗尽、账本字段保留均有原生服务验证。
