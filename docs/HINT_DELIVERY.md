# 人工提示投递

更新：2026-11-03。适用于单 API 实例、SQLite 及当前 Pi SDK。

智能体工作台可选择“当前会话”或“任务规划（Planner）”。提示须为 1～2000 字符非空文本。任务不存在或会话不属于任务返回 404；任务或指定会话已结束返回 409。创建提示和 hint.create 审计同事务；保存成功不表示模型已收到或采纳。

## 当前会话

提示保留精确 agentSessionId，不能被 Planner 的任务提示查询读取，也不转给其他 Worker。活动会话使用 SDK steer 排队，在下一轮边界进入上下文，不调用 prompt 打断活动流。每秒巡检重试本地入队，当前进程按提示 ID 去重。入队前重查任务/会话状态、执行开关及 Worker 分配和租约。

入队后仍是 pending。SDK 实际产生该条 user 消息时，同一事务保存完整消息并将提示改为 consumed，appliedToSessionId 为原指定会话；消息以提示 ID 作为稳定 ID，重复接收不重复插入。消费仅表示进入会话记录，不证明后续模型请求成功、模型采纳提示或测试目标已达成。提示不能绕过范围、权限、审批和预算。

提示接收落库失败时回滚消费和消息，终止本会话的继续派发并记录失败，保留 pending；不把保存失败当成已送达。实时推送失败不改变已提交消息，可重新读取历史。

暂停不启动模型。中止后清空 SDK 未接收的提示队列和内存去重标记，未消费提示留在数据库；用户明确恢复原会话时重新入队。既有预算规则仍有效：中断模型流导致用量未知时，不能用人工提示绕过未确认占用。实际恢复可能需要通过任务控制和新的明确预算/会话处理，不能承诺所有中断均可原地继续。

进程重启后，遗留活动会话标记为失败；定向 pending 提示仍属于原会话，不自动重放或转投新会话。若提示尚未被接收而会话已自然结束，提示也保留 pending 历史；用户核对后可向当前会话或任务规划重新提交。

## 任务规划

不指定 sessionId（或 broadcast=true）表示任务提示，交给 Planner 的后续规划轮次，不表示向所有 Agent 同时广播。Planner 只读取此类 pending 提示；本轮产生并接纳结构化规划后消费本轮读取的提示。该类型不强制打断已有工作、不自动恢复暂停/停止任务，后续 Worker 根据实际意图与证据上下文工作。

## 验证

`npm run test:hints` 使用真实完整 Nest 路由、显式迁移临时文件库、真实 Pi Agent 和仅回环地址的固定 OpenAI 兼容流。覆盖非空/长度/归属、审计回滚、两个 Worker 与 Planner 的隔离、真实下一次模型请求、并发入队去重、消费与消息同事务及幂等、暂停后明确恢复、接收故障不继续派发、任务/开关/租约门禁，以及关闭再打开临时库不重放。一个固定等待工具仅等待本地 AbortSignal，不访问任何目标。

界面交互测试验证目标选择、实际请求 sessionId、提交期间禁用、终态定向阻止、任务提示失败原文保留及历史归属显示。该验证不代表真实模型一定遵循提示。
