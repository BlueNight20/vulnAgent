# 运行日志

更新：2026-11-03。生产入口 dist/main.js 使用统一 RuntimeLogger；模型、任务、MCP 和应用框架的 Nest 日志采用相同过滤与文件输出配置。

## 操作与生效

设置页选择 debug / info / warn / error，并可勾选“保存运行日志到文件”。切换只改变草稿，点击保存后生效。数据库已保存值优先于 LOG_LEVEL / LOG_TO_FILE；重启后继续使用数据库设置。文件目录由 LOG_DIR 决定，相对 API 工作目录，修改目录需要重启。

debug 包含全部级别；info 隐藏 debug / verbose；warn 只记录警告、错误和 fatal；error 只记录错误和 fatal。文件与控制台使用同一过滤。启动早期尚未读取数据库时，控制台按环境级别输出；数据库配置在应用监听之前应用，之后的模块初始化与运行日志使用保存的设置。

文件名为 LOG_DIR 下的 vulnagent.jsonl，每行一个 JSON 对象，包含 UTC 时间、级别、message 和 details。文本中的换行会编码在 JSON 字符串中，不会冒充新记录。内容有长度上限，适合排查运行状态；它不替代数据库中的完整工具证据、会话结构化消息、审计和报告。

## 保存失败与运行故障

保存时先在数据库事务中写设置和审计、生成配置响应并预先打开目标文件，提交后才切换级别与文件句柄。路径/权限不允许时返回 503 并回滚设置；审计或提交失败同样回滚，保留原日志行为。预检查可能创建目录或空日志文件，但不会在失败的配置下记录运行日志。

文件输出期间遇到磁盘、权限或句柄写入错误，停止文件写入并在控制台报告。GET /api/settings 的 loggingStatus 返回实际 level、fileEnabled、directory、activeFile 和 lastError；配置请求 logToFile=true 与故障后的 fileEnabled=false 可以同时出现。页面重新读取后显示实际状态和原因。修复目录/磁盘后，重新保存即可打开文件并清除错误状态。

应用启动时无法打开已启用的日志路径会拒绝启动，不会假装文件日志正常。恢复目录权限或将 LOG_DIR 指向可写目录后重启；环境 LOG_TO_FILE=false 不会覆盖已经保存的数据库开关。

日志追加到普通文件；关闭文件输出不会删除既有文件。本版本不安装日志清理任务、不自动轮换或删除历史记录，操作者按需要停止文件输出并归档，再重新启用。数据维护页清理任务和备份轮换不会自动清理日志。日志目录不是数据库备份的一部分。

## 脱敏边界

统一日志对当前及近期轮换的模型 API Key（最多 64 个）做原值替换，同时遮蔽常见 Bearer / Basic、apiKey / Authorization / password 文本。文件和控制台均使用处理后的文本；测试只用固定假凭据。此规则不识别所有任意业务秘密，原始工具证据仍依照证据存储策略保存，不能把文本过滤称为通用内容脱敏器。

## 验证

`npm run test:logging` 使用临时目录、真实迁移数据库、SettingsService / AuditService / Nest HTTP，以及真实 main.js 子进程。覆盖级别过滤、仅控制台、文件开关、预检查/审计/提交失败回滚、JSONL/换行/已知凭据过滤、文件写入失败的实际状态、重开与禁用、真实入口保存生效和进程重启后的数据库优先级。未读取用户 .env、业务库或联系模型/靶机；不会在工作区创建运行日志文件。
