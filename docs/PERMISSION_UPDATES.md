# 工具权限维护与审计

MCP 管理的权限页编辑全局规则，展示常用模式、已保存的自定义模式，以及当前返回的目录工具精确名称。可以筛选工具名或模式，单独调整授权与审批要求；也可填写精确工具名或通配模式新增规则。新增表单默认不授权、要求审批，点击保存才写入。目录展示由接口限制最多 200 个工具；不在当前列表中的名称仍可手工填写，已保存规则不会因工具从目录消失而隐藏。

“未配置”表示没有这条规则，不能等同于“显式拒绝”。开关只表示当前规则，实际执行仍合并全部匹配规则：显式拒绝优先，无匹配默认拒绝，任一有效授权要求审批即保留审批。修改需审批开关不会执行工具；目录标记为 destructive 的工具仍需审批。新规则也不会绕过 Worker 档案、目标范围、实际 Schema 或预算。完整匹配规则见 PROFILE_PERMISSIONS.md。

权限保存时串行执行查找/创建或更新，并将修改前 allowed / requireApproval 一起写入 mcp.permission_update 审计。新建的 previous 为 null。权限与审计同一事务，审计或提交失败整体回滚，界面显示错误，不提前显示或推送成功。成功提交后才发送 audit.appended。WebSocket 断开导致的推送失败会记录告警，已提交权限和审计保留，HTTP 仍返回成功；客户端可重新读取。

不同客户端同时编辑同一规则按实际提交顺序生效，每次修改都有原值审计；本接口没有 expectedRevision，不承诺阻止最后提交覆盖较早提交。省略 requireApproval 时保留原值，新规则默认 false。UI 新增表单选择 true 是界面默认值。权限页只编辑全局规则；任务级设置仍通过带 taskId 的 API，且只能写入现存任务。请求格式和状态码见 API.md。

## SQLite 唯一性与升级

SQLite 原 `(taskId, agentRole, toolPattern)` 复合 UNIQUE 不能阻止 taskId=NULL 的重复全局规则。第十条迁移增加 `IDX_agent_permission_global_unique` 部分唯一索引，限定全局规则的角色与模式唯一；现有任务级唯一索引保持。

若旧库已有同角色、同模式的全局重复组，迁移保留按 createdAt / id 排序的首条 ID，只在所有原规则均允许时保存 allowed=true，任一原规则要求审批时保存 requireApproval=true。存在拒绝的组仍被拒绝；若日后人工开启该组，审批要求仍保留。迁移将该组的全部原记录、保留 ID 和结果写入 mcp.permission_duplicates_merged 审计，然后合并记录并建立唯一索引。不会给新角色或工具新增授权。

重复组含非 0/1 布尔值、审计无法保存或已有同名索引结构不符时拒绝升级，事务整体回滚。应用文件库仍有既有迁移前一致性备份流程。迁移 down 仅移除新索引，不删除合并后的有效规则与审计，也不会恢复重复行；要精确回到升级前文件应使用迁移前备份，参见 BACKUP_RECOVERY.md。原九条迁移未重新生成，当前 31 表 / 10 迁移 / 25 张任务所属表。

## 验证

`npm run test:permission-updates` 使用真实迁移 SQLite、Nest HTTP、校验管道、权限服务和审计服务。覆盖旧重复组的允许/拒绝及审批语义、全部原记录审计、异常布尔值拒绝、审计失败回滚、索引漂移拒绝、数据库唯一约束、重复迁移和索引回滚；HTTP 创建/更新、原值审计、创建/更新失败回滚、提交失败不推送、并发服务实例不重复建规则、审计值链、任务/全局隔离、无效参数及推送失败后的持久化。网关替身同步检查推送时事务已结束、审计行已提交。

界面测试验证精确工具与自定义模式、审批值保留、明确拒绝/未配置、新增规则默认值、错误反馈、加载期禁止写入及任务规则不冒充全局值。不执行工具、命令或靶机请求，也不改动用户现有数据库。
