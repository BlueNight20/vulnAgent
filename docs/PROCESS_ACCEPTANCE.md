# 完整应用进程联调

更新：2026-11-03。命令：`npm run test:process-e2e`。

测试启动实际编译后的 `apps/api/dist/main.js` 子进程，使用临时工作目录、独立迁移数据库和假凭据。所有业务操作经真实 HTTP 接口完成，不直接插入意图、事实、候选、验证结果或报告。模型和 MCP SDK 都是真实依赖；本机协议服务只返回固定数据，不启动扫描程序，不提供靶机服务，不访问测试数据中的目标地址。

## 成功流程

1. 启动生产入口并检查健康；通过 MCP 管理 API 同步固定协议工具目录。
2. 通过任务 API 创建带明确范围、模型及 assessment 目标的任务，再通过引擎 API 启动。
3. 真实 Planner Session 从固定模型协议取得两条结构化意图，调度两个独立 Worker；两个 MCP 请求实际重叠，检查并发路径。
4. 工具返回固定原文，经策略、Schema、证据入库和事实提取，形成候选。模型仅引用系统真实返回的证据 ID。
5. 后续 Planner 请求包含实际落库证据；分析 Worker 引用已有证据，独立 verifier 发起新的 MCP 调用并引用新证据原文，候选形成有效复核记录。
6. 任务目标逐项满足后完成，通过报告 API 生成和导出冻结快照。只读核对数据库证据哈希、Worker 结果和 Planner 会话数量。
7. 终止并重新启动后端子进程，确认已完成任务、候选结论及报告来源保留，没有新增模型或工具调用。

测试数据使用文档地址 192.0.2.10，报告标题明确标注固定协议。协议中的工具名用于验证现有调度和参数路径；处理器只返回常量文本，不调用对应扫描器或发送目标 HTTP 请求。测试报告随后随临时目录删除，不作为真实安全结论交付。

## 执行中断与恢复

创建另一任务，等待实际模型请求处于未结束流并已预留额度时，终止后端子进程。重启后检查：

- 旧 Session 标记为进程中断，没有捏造工具证据。
- 未结算模型请求为 uncertain，未知消耗不当作零费用，预留余额继续占用。
- 原先有执行上下文的任务转为 paused / needs_input，提示核实远端状态及用量后人工恢复。
- 完成后的任务不受影响；中断任务也不会自动重发模型或工具调用。
- 存在 engine.recovered 审计。另由生命周期集成验证恢复时旧控制请求失效，任务/控制请求/恢复审计同事务；注入审计故障会整体回滚该事务。

启动对账由 Orchestrator 在事件消费之前执行，不再额外安排延迟会话清理，避免把启动后新建的会话当成遗留记录。恢复到暂停不代表撤销远端副作用，也不替代用户核查真实工具是否已经停止。

## 安装与范围

`npm run test:clean-install` 将清单、锁文件、编译产物和测试脚本复制到全新临时目录，执行 npm ci，然后重复包括本测试在内的 8 组关键验证。不会复制用户 .env、storage 或业务库；此结果证明当前 Windows / Node 环境的安装及运行路径，不等同于源码从零构建或跨平台验收。

API 现默认监听 127.0.0.1，可用 VA_API_HOST 显式配置；前端开发代理默认指向同一 IPv4 回环地址，避免 localhost 解析到 IPv6 时连接不到后端。此设置不代替鉴权，Vite 开发服务器代理也不是生产访问控制。

以上证明固定协议下的进程与数据链路、并发和恢复行为，不证明真实模型的推理质量、真实靶机漏洞准确率或真实远端工具取消效果。靶机实测按分工由用户执行，代码与本地验证继续由开发侧完成。
