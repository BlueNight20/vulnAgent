# 执行引擎开关

更新：2026-11-03。适用于当前单 API 实例的单人 SQLite 版本。

## 设置与生效

设置页的“启用执行引擎”显示实际读取值，切换仅修改草稿，点击“保存配置”才生效。也可 PUT `/api/settings`，请求体为 `{"runtime":{"piRuntimeEnabled":true}}`。没有数据库设置时读取 PI_RUNTIME_ENABLED，默认 false；已保存的数据库值优先。缺失密钥、解密失败等错误仍明确返回，不以其他凭据替代。

关闭与设置更新、审计、运行任务的 paused 状态、旧启动/恢复控制失效及 runtime.disabled 事件同一事务提交。审计或响应配置读取失败整体回滚。事件由编排器消费，暂停会话及在途工作；关闭事件尚未收尾时启动/恢复返回 409，稍后手动重试。

重新开启只允许后续执行，不自动恢复任务。先确认外部工具状态，再到任务页手动恢复；待启动任务使用启动引擎操作。关闭时仍可保存 autoStart=false 的任务，autoStart=true 则返回 409 且不创建记录。重新运行可准备新一轮 pending 任务，实际启动仍受开关限制。

## 控制边界

- 编排启动/恢复、会话启动/恢复、Worker 创建均检查当前设置。
- 模型请求在等待并发槽之后、预留预算之后及实际派发前检查；尚未派发的预留取消，不计为供应商未知消耗。
- 任务关联的 MCP 工具在缓存命中之前及实际派发之前检查，包括已批准调用的重放。关闭期间不会把旧缓存作为新执行成功。
- 已发出的模型/工具调用通过已有暂停及取消机制收尾；取消通知不能证明远端进程已经停止，未知结果须由操作者核实，不能自动重放有副作用的操作。
- 手动模型连接测试、MCP 健康检查及目录同步属于配置操作，关闭引擎后仍可显式执行，它们会联系已配置端点。

没有数据库和网络之间的分布式原子提交；最后检查之后已开始派发的请求属于在途操作。开关不是远端进程急停保证。关闭任务记录会先于异步会话收尾，不以页面显示 paused 作为远端已停止证明。

## 验证

`npm run test:runtime-control` 使用真实迁移的临时数据库、Nest HTTP、设置/任务/预算/审批/执行服务和固定本地工厂。覆盖默认关闭、数据库覆盖、关闭不创建自动启动任务/会话/运行记录、事务故障回滚、旧控制失效、缓存和审批重放拦截、快速重新开启不恢复、手动恢复、等待并发槽期间关闭、预留之后关闭及未派发预留取消、重新启用后派发。界面测试覆盖草稿/保存/重新读取及保存失败。该验证不访问靶机，也不证明实际工具响应取消的效果。
