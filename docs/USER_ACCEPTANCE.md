# 单人使用与靶机验收

更新：2026-11-03。代码开发和隔离验证由开发侧负责，真实靶机测试由用户操作。当前支持单 API 实例、SQLite、本机管理台；无需账号系统。PostgreSQL 尚未完成适配。

## 首次配置与启动

在项目根目录使用已验证的 Windows / Node 24.21.0 环境。首次安装执行 `npm ci`；已有安装无需重复安装。首次没有 .env 时按 README 配置，也可使用 `powershell -File scripts/start.ps1`，该脚本只在 .env 不存在时创建配置，不覆盖已有文件。已有服务运行时先自行结束对应终端，再启动新版本，避免重复占用端口。

开发启动为 `npm run dev`。生产构建为 `npm run build`，API 启动为 `npm run start --workspace @vulnagent/api`。前端构建产物位于 apps/web/dist，需另行静态托管并将 /api 与 /ws 代理至后端；API 不负责提供前端静态页。本机自用可直接采用开发启动方式，管理台默认 http://localhost:5173，健康接口 http://localhost:3001/api/health。

按以下顺序配置：

1. 保持 DB_TYPE=sqlite、DB_SYNCHRONIZE=false，核对 DB_PATH；不要用自动同步代替迁移。API 启动会运行显式迁移，旧库结构漂移会拒绝启动。主密钥与数据库分别保管，恢复旧库必须使用原主密钥，见 BACKUP_RECOVERY.md。
2. 在设置页填写并保存模型地址、模型和 API Key，再点击连接测试；测试联系真实供应商，成功不代表模型一定适配所有工具或复杂推理。任务创建时核对所选模型。
3. 用户自行启动既有 blhackbox，在 MCP 页检查网关地址、检测状态及工具目录。连接失败时核对 URL、认证头、网络和网关日志；本系统不启动或改动 blhackbox。
4. 核对角色权限，尤其 verifier 的目标验证/审计工具。已有规则不会被默认档案自动放宽，显式拒绝优先；需要调整时通过权限页保存，保留原值审计。
5. 设置页开启执行引擎并保存。默认关闭；数据库设置优先于环境值。修改并发、预算等配置后核对保存结果。引擎开关控制见 RUNTIME_CONTROL.md。

MCP 连接配置页当前为只读。环境配置启动时只导入新名称，同名已有服务保留数据库中的地址和认证头；修改环境变量不会覆盖旧连接。首次配置应在启动前核对，不把页面展示当作已完成连接修改；现有连接变更须另行备份并处理配置迁移。

日志级别和“保存运行日志到文件”保存后即时生效；页面显示当前实际级别、文件路径或错误。默认不写文件，开启后追加 LOG_DIR 下的 vulnagent.jsonl，不自动删除旧日志。目录不可写会使保存失败并保留原配置；磁盘写入故障后重新读取设置查看实际状态，修复后重新保存。详见 LOGGING.md。

## 首次靶机任务

先使用一个明确授权的实验目标及较小端口范围，填写目标、授权声明、时间/Token 预算和验收目标。首次可使用一个 Worker 观察过程，再按需要扩大并发。IP、CIDR 与端口授权范围应与本次实验相符，不要通过放宽全局权限解决目标填写错误。

在任务中心创建任务后，在工作流或智能体页选中该任务并点击“启动引擎”；如创建请求使用 autoStart=true，则通过持久化事件请求自动启动。关闭引擎时自动启动请求返回 409，不会留下新任务。

新任务抽屉每次打开读取保存的模型和默认预算/Worker 数量，后台刷新不覆盖正在填写的草稿。全局 Worker 上限是所有任务合计，包含派发排队；任务自身数量可以更高，等待名额时系统自动继续，不增加重试或无进展次数，但仍计算时间预算。降低全局上限会等待已有任务收尾。具体规则见 WORKER_CAPACITY.md。

观察 Planner 意图、Worker 会话、工具参数、原始证据与攻击面更新。工作流展示真实执行关系。需要审批时先查看具体工具、目标和参数再决定；批准仍需通过当前范围与权限检查。不要把工具“成功返回”直接当成漏洞已证实。

长会话每页显示最多 300 条消息，可点击“加载后续消息”继续查看。操作失败会显示原因，不会自动重试；工作流中的暂停任务使用“恢复引擎”。会话列表中的消息数量包含全部记录，列表文本为预览，完整工具输出请打开对应证据。

会话消息下方可展开“完整会话消息（含工具参数）”，查看保存的 SDK 结构、调用参数及超过文本预览的内容；原始完整工具证据仍在证据管理中。

人工提示选择“当前会话”时只进入指定会话；选择“任务规划（Planner）”时供后续规划读取。已消费表示进入记录或本轮规划已处理，不表示模型一定采纳。暂停时保留等待，重启后原会话的未消费提示不自动转投新会话。若模型中断留下未知用量，仍须按预算与恢复规则处理；提示不会绕过限制，见 HINT_DELIVERY.md。

工作流的 Planner 连线来自意图保存的来源会话，Worker 提出的后续意图显示为 Worker 分支，已完成前置意图及证据反馈分别显示。节点中可查看保存的 Worker 输入/输出和 Planner 最近输入/输出文本预览，完整 Planner 消息在智能体工作台查看。

控制接口成功表示请求已接受，随后等待页面重新读取实际状态；不要立即交叉点击任务中心与引擎控制。暂停、等待输入或停滞时使用恢复；终态先重新运行，再等控制处理完成后启动。恢复保留原 Token 和时间预算。详细返回格式及中断语义见 ENGINE_CONTROLS.md。

漏洞候选在漏洞页查看来源并安排独立验证；确认结论应可跳转到本次 verifier 的新调用及连续原文。无法确认应保留原因。描述、评级、CVE/CWE、CVSS 和修复建议维护需要引用证据，维护不会改变独立验证状态。

验收目标完成或手动停止后，在报告中心生成并导出 Markdown / PDF / JSON / ZIP，核对目标、范围、确认与未确认结论、证据引用及附件。报告为冻结快照，后续维护不修改旧报告；修改后需生成新报告。

## 用户执行的验收记录

| 项目 | 预期结果 | 建议保留 |
| --- | --- | --- |
| 信息收集 | 实际工具调用与授权目标一致，端口/服务状态有对应原始输出 | 任务 ID、工具调用 ID、工具与目标独立核对结果 |
| 动态探索 | 后续意图利用已落库发现，失败有原因且不无限重试 | Planner 意图、前后证据 ID |
| 并行 Worker | 多会话按配置运行，Token/时间/工具限制生效 | 会话 ID、时间线与预算账本 |
| 人工提示 | 定向提示仅指定会话可见，暂停不自动恢复，任务提示供后续 Planner 使用 | 提示 ID、目标/实际会话 ID、会话消息及状态 |
| 独立复核 | 候选与复核来源分开，无证据时不强行确认 | 漏洞 ID、验证历史、复核原文 |
| 权限审计 | 审批参数与实际远程目标一致，输出能证明目标身份和权限 | 调用、远程会话与目标身份材料；MCP 宿主机权限不算靶机权限 |
| 暂停/恢复 | 暂停后不继续派发新工作，恢复由用户发起 | 调用时间线及远端进程状态 |
| 关闭执行引擎 | 运行任务暂停、新请求受阻；重新开启不自动恢复 | 设置保存结果、任务与会话状态 |
| 报告 | 引用可追溯、中文正常、附件可下载，旧快照保持原内容 | 报告 ID、导出文件及问题位置 |

上述为用户待执行项目，开发侧的固定协议测试不替代这些结果，也不承诺真实漏洞发现率或提权成功率。

## 中断、恢复与维护

暂停/停止会请求取消在途调用，但不能证明网关或靶机上的远程进程已经退出。关闭引擎同样如此。先自行核对远端执行状态，再恢复或重跑。审批结果未知时按页面的人工核实流程处理，不盲目重放。进程退出后的模型用量未知会保留占用，不伪装成零消耗。

遇到 409 先读取错误说明：可能是控制事件仍在处理、任务状态冲突、预算或清理条件变化，不必反复点击。模型连接失败先看已保存地址、模型和凭据；MCP 无工具先看检测/同步结果及角色权限。密钥无法解密须恢复原密钥，不要删除密文或随机更换主密钥。

备份、校验、新路径恢复及保留轮换见 BACKUP_RECOVERY.md；设置页手工清理见 DATA_MAINTENANCE.md。清理应在任务收尾后预览并核对备份路径，数据库发生变化须重新预览。恢复只写新路径，由用户停止 API、核实远端状态后切换 DB_PATH 和原主密钥；保留原库以便回退。

反馈问题时提供任务/会话/工具/漏洞或报告 ID、操作步骤、时间、期望与实际结果、界面错误及脱敏日志。涉及取消、重启或重复调用时补充远端是否执行/停止的确认结果。不要发送 API Key、请求认证头或主密钥；含敏感原始数据的证据需先核对分享范围。
